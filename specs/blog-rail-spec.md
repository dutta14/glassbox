# Blog rail and reading pane: spec

Source of truth for the rail / reading-pane redesign. The visual reference is `blog-rail-mock.html` (open it in a browser; section 8 of the mock is this table). `blog-rail-plan.md` records where the real app departs from the mock.

| Area | Spec |
|---|---|
| Rail surface | --color-bg (same as page). No border-right. Width 272px (was 248px) to hold wrapped Garamond at 14px. |
| Padding | 34px top, 28px left, 14px right, 14px bottom. Left edge of masthead, year labels and the ◇ column align at 28px. |
| Masthead | Garamond 30px / 1, --color-text. Tagline Garamond italic 15px, --color-text-muted, optional and user-editable. |
| Action links | Inter 13px, --color-text-secondary, underlined 4px offset in --color-border-strong. Order: New, Search. New carries a caret and opens Prose / Verse. Collections is now a tab, not a link. |
| Year heading | Inter 13px, 0.12em tracking, --color-text-muted. Hollow 6px ◇, 1px rule at 60% of --color-border-strong, count (12px, tabular), chevron. Sticky, page-colour background. A full-row button: aria-expanded, controls its list. |
| Collapsed | No rail at all. A 40px menu button (aria-label="Open sidebar", 3-line icon) sits 20px from the top left, --color-text-secondary, raised background on hover. The page uses the full width. State is remembered per device. |
| Note row | Garamond 14px / 1.25. Rest --color-text-faint (same as the date); hover and the selected note only --color-text. Row padding 6px 28px 7px 16px, 4px gap between rows. Title wraps (overflow-wrap: anywhere). |
| Date line | Inter 11px, 0.08em tracking, uppercase, --color-text-faint. Under Posts: “MONTH D” (the year is the heading). In search results: “MONTH D, YYYY”, followed by the collection name when the post is in one. Collection rows carry a chapter count instead of a date (see Posts / Collections). |
| Reading feed | The middle pane shows posts that are not in a collection, newest first, as a continuous feed; or, while searching, a flat feed of every match. It does not follow the tab: switching Posts / Collections never changes the pane. Four posts load at first; four more load when a sentinel comes within 400px of the bottom, with a 450ms “Loading more…” state, ending in “That’s everything.” Posts are separated by 140px and an ornament. The first post never touches the top edge: the pane has 72px of top padding (56px under 900px), so the title starts well below the window edge and lines up with the masthead’s breathing room; the same padding applies above the editor and a collection page. It scrolls away with the content. Each is an <article aria-labelledby>; the pane is <main>. Clicking a rail row scrolls the feed there (smooth, instant under reduced motion) and loads forward as needed. The open post is part of the route, not the hash (the app uses a HashRouter), and the route is replaced, not pushed, as you read. Search resets the feed to the top. A long library should window or unload posts far from view; the verse measuring runs only in the editor, so it never runs per feed post. |
| Writing | New and Edit replace the main pane with the existing editor; Done or Esc returns to the same post (or, when editing a chapter from a collection page, to that collection at that chapter). New always switches to Posts, closes search and opens a draft at the top of the current year. Autosave, no Save button; an empty new draft is discarded on close. Choosing a collection happens afterwards from the ⋯ menu. Starting another action while writing saves first. Out of the app: nothing is created until the first keystroke, so New then Done leaves no trace. |
| Selected marker | Follows the post being read: as you scroll, the ◇ and full ink move to the post crossing the reading band (25% down the pane), and the rail scrolls itself to keep the row in view. In the editor it marks the note being written. Filled 6px ◇ in --color-text at x=3px. Hover shows the same ◇ hollow at 55%. Verse titles are italic everywhere in the rail. |
| ⋯ menu | 26px target at the row’s top-right, hidden at rest, shown on hover, focus-within or when open, and always on touch (hover: none). Same items as today. |
| Focus | Existing --shadow-focus ring around the row link or heading, 4px radius. Search input has no ring; the underline thickens instead. |
| Motion | 150ms colour / opacity, 150ms chevron turn. All off under prefers-reduced-motion. |
| Grouping | Posts tab: by createdAt year, newest first, all open by default, fold state per session. A year holding the selected note or a search match is forced open. Invalid dates fall into a final “Undated” group. |
| Tabs | Posts and Collections under the action links. Garamond 16px, no rule or underline; the open tab is --color-text, the other --color-text-faint. role="tablist", arrow keys move between tabs, the list is the tabpanel. The open tab is remembered per device. While searching the tabs are hidden (see Search) and return when search closes. |
| Posts / Collections | Posts: notes without a collection, grouped by year, then “New” lives in the action links. Collections: a flat list of collections, one row each: the name (Garamond 14px, same row as a post) and beneath it “N chapters · YYYY–YYYY” (Inter 11px, uppercase, 0.08em, faint; “1 chapter”; the years are the first and last year in the chapters’ written dates, a single year reads “2011”, never “2011–2011”; “Empty”, with no years, at zero). No year headings, no collection headings, no fold, no posts underneath. Ordered by most recently updated. The open collection takes the filled ◇ and full ink, as a post does. Below the list: “New collection”. No Organize menu. A collection’s posts never show under Posts. The existing BookListItem is this row. |
| Collection page | Opens in the main pane when a collection is chosen in the rail, or its line is followed from a post. Title (Garamond 44px), “N chapters · YYYY–YYYY” beneath (Inter 12px, uppercase; same years rule as the rail row), the ornament, then every chapter as an article in the collection’s own running order (the order chosen on the page, not by date). No infinite scroll and no loader: all chapters render, as BookStage does today. Ends with “End of Name.” Each chapter ends with a quiet line: its written date, then “Edit” and “Remove from collection” (Inter 11px, uppercase, 0.08em, faint; the date is “MONTH D, YYYY”; no “Written” and no read time here). These are the two actions the app has today. Done returns to the page at that chapter. Rename and reorder stay as in BookStage. Empty: title, “Empty”, “No chapters yet.” The mock orders chapters by date, oldest first, as a stand-in for the running order. |
| Search | Inline, not a modal. “Search” swaps the New / Search links for a field in the same spot (Garamond italic 17px, underline only, no box). While it is open the Posts / Collections tabs are hidden and the list becomes one flat set of results from every post and every collection, newest first, with no year or collection headings. Each row’s date line carries the year and the collection name. A small count (“3 results”) sits above the list. Matches title, body and tags, as the modal does today. A match wash marks the title hit; a body-only match shows one muted line of text under the date (this mock filters titles only, so the snippet is not shown). Empty field: “Search every post and collection.” No results: “Nothing matches “zzz”.” Esc or the “esc” button closes search, restores the tabs, the previous tab and fold state. Field: role="searchbox" labelled “Search notes”; the count is a polite live region. No scrim, no focus trap, so the page stays readable and clickable. |
| Collection line | Shown on any post that is in a collection: in the feed (search results only, since the Posts feed holds no collection posts), on the collection page chapters’ editor, and in the editor. Copy: “In the collection – _Name_” (the real app says “In the Book - ” today; the hyphen becomes an en dash). Inter 12px / 1.6, 0.08em tracking, uppercase, --color-text-muted; the name is a link underlined at rest, 4px offset, --color-border-strong, full ink on hover and focus. Spacing: 20px under the title’s last line (the old −8px pulled it into the title), then the ornament 22px below, measured from the line’s box. Centred, max 30em, wraps on long names (overflow-wrap: anywhere). An empty name reads “Untitled collection”. Not shown for a post outside a collection. The link goes to that collection’s page, scrolled to this chapter (the existing /book/:id route with a chapter target); the rail switches to Collections and marks the collection. From the editor it saves first. |
| Search highlighting | Search matches title, body and tags, case-insensitive, as a substring. Every occurrence is marked with <mark> (--color-raised wash, full ink, 2px radius, 1px side padding), never a bright colour. Marked in three places: the rail row’s title; the rail row’s body snippet (shown only when the title has no hit: one line of text around the first hit, about 40 characters before, clipped to two lines, with … at a cut end); and, in the feed, each result’s title and body. Marks are cleared when search closes or the query is emptied. The feed scrolls to the top of the first result, not to a hit inside it. No “next match” control in this iteration. Screen readers hear the text unchanged (mark is not announced as a change). |
| Row ⋯ menu actions | Post rows. Turn into prose / verse: the post re-renders in place in the feed and the rail title goes italic or upright; nothing moves. Add to collection: opens a small list of collections (plus “New collection”); on choosing, the post leaves Posts, joins that collection as its last chapter and the feed and marker advance to the next post below (the one above if it was last). Delete: keeps today’s confirmation; afterwards the marker and feed move to the next post below, or the one above, or to the empty state if none remain. Collection rows. Delete collection only, with the existing confirmation. The posts are kept and return to Posts in their year. Rename, reorder and “Remove from collection” live on the collection’s page, where the chapters are. A collection whose last chapter is removed stays, “Empty”, until deleted. |
| New collection | The link turns into a one-line name field (Garamond italic 17px, underline only, same as search). Enter creates an empty collection and opens its page; Esc cancels; an empty name is ignored. An empty collection shows “Empty” in the rail and, on its page, the title, “Empty” and “No chapters yet. Add a post from its ⋯ menu.” |
| Feed & rail agreement | One invariant: the marked row is the thing in the main pane. On Posts that is the post in the reading band, or the note in the editor; it changes on scroll, on clicking a row, on Done, on New, and on search. On Collections it is the open collection, and the pane shows its page. Following a collection line opens the page and switches the rail to Collections. If the marked post is in a folded year, that heading is forced open. If a post is not yet loaded, clicking its row loads forward to it, then scrolls. If the list changes under the reader (search), the feed resets and the marker goes to the first post, except closing search, which keeps what was open before. |
| Deep link & reload | The URL hash is the open post’s id. Opening a URL with a hash loads forward to that post and scrolls to it; an unknown or deleted id falls back to the first post and drops the hash. Back and Forward do not step through every post scrolled past (replaceState). The open tab is remembered per device, so a hash for a post in the other tab switches tabs. |
| Empty and first-run states | No notes: rail shows “Nothing here yet. Start with the first line.”, the feed shows the same centred in the page and New stays available. Sample notes banner above the first year until deleted. No collections: the Collections tab shows its empty message and “New collection”. An empty collection’s page: its title, “Empty”, “No chapters yet.” Search with an empty field: “Search every post and collection.” No results: the feed says “Nothing to show.” |
| Keyboard | Tab order: masthead, collapse, New, Search, tabs, headings and rows, then the page. Enter on a row scrolls the feed and keeps focus on the row. Each post’s Edit link is reachable by Tab in the feed. In the editor: Esc or the Done button returns to the feed. In search: Esc closes. Left and Right switch tabs. The feed pane is tabindex="-1" so it can take programmatic focus after Done. |
| Small screens | Under 900px the rail is a drawer. Choosing a row closes the drawer and scrolls the feed to that post. The feed runs full width with 20px side padding, a 96px gap between posts, and titles at 32px. The collection line and Edit link wrap rather than truncate. |
| Dark mode | Every colour above is a token, so nothing is hard-coded. Marks use --color-raised, which stays visible on the dark page. Ornaments and rules use the same tokens as today. |
| Performance | The feed renders four posts, then four per page. Past about 60 loaded posts, posts far above the viewport are replaced by fixed-height spacers so scroll position holds. Scroll-spy uses one IntersectionObserver, never scroll events. Search runs on the client over all notes; results render in the same pages of four. |
| Removed from the app | The search modal (NoteSearchModal, with its dialog, backdrop and focus trap), the Organize menu and its kebab trigger (OrganizeMenu), the “In one list / By book” options and their copy (organizeOptionList, organizeOptionBook), and the OrganizeMode preference (useNoteOrganize, key glassbox.notesOrganize.v1). The rail’s separate Notes and Books sections and the Books entry go too; the Posts / Collections tabs replace them. Unchanged: BookListItem (the collection row) and BookStage (the collection page, with its contents, rename and reorder). Tests that assume the “list” default or the book-grouped Notes section are rewritten for the tabs. |
| Accessibility | Each year is <h3> wrapping the toggle button, each list a <ul> labelled by it. Selected row keeps aria-current. ◇ is decorative (aria-hidden). Contrast of faint text on page background: 4.9:1 light, 5.9:1 dark. |
